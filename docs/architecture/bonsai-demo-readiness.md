# Bonsai Demo Readiness

Status: working plan, 2026-07-21.

This note defines the shortest clean path from the current runtime foundation
to a credible Bonsai 27B demo. It is intentionally a demo-readiness plan, not a
new architecture authority. The authoritative runtime contracts remain
[`inference-runtime.md`](inference-runtime.md) and
[`inference-runtime-contracts.md`](inference-runtime-contracts.md).

## Demo Definition

The first acceptable demo is a local candidate run on the inference VPS:

- plaintext execution only;
- PVAC unavailable and fail-closed;
- one rooted target generated by `octra-inference`;
- one admitted LiteNode program with an execution requirement;
- one target-owned generation path;
- rooted request, output, and local evidence;
- exact canary token and internal-root checks; and
- clear labeling as non-consensus candidate evidence.

The demo is not ready to claim consensus execution, encrypted inference,
network admission, or publisher endorsement.

## Current State

| Surface | State | Next acceptance condition |
| --- | --- | --- |
| Clean fork | Branch starts from current LiteNode head | Keep changes isolated and reviewed |
| PVAC boundary | Explicit unavailable backend builds | No plain inference path invokes PVAC |
| Opcode policy | Centralized classification | New opcodes enter through one policy |
| Requirement admission | Exact root and limit matching | `octra-inference` emits matching roots |
| Target admission | Root binding module added | Wire target descriptor into a harness |
| Ontology guard | Runtime source scan added | No model-family names enter VM code |
| Tensor substrate | Not started | Add only generic accepted primitives |
| Sessions | Not started | Add local open/advance/finalize runner |
| Receipts | Not started | Emit semantic receipt plus diagnostics |

## Handoff Shape

`octra-inference` should hand LiteNode the following candidate packet:

| Artifact | Owner | LiteNode use |
| --- | --- | --- |
| Program bytecode and certificate | `octra-inference` | Existing program verifier and policy |
| Execution requirement | `octra-inference` | Exact support check and root binding |
| Inference target | `octra-inference` | Program, requirement, data, and ABI roots |
| Request | `octra-inference` | Prompt tokens, generation policy, and seed root |
| Model store locator | `octra-inference` | Authenticated immutable range access |
| Canary evidence | `octra-inference` | Qualification input, not VM admission proof |
| Local receipt | LiteNode | Output root and semantic execution evidence |
| Diagnostics | LiteNode | Timing, residency, cache, and binary roots |

The only public boundary is the rooted target plus request. Model parsing,
tokenizer rendering, family-specific execution semantics, and qualification
evidence remain outside LiteNode.

## Next Build Slices

1. Add a small local admission harness that reads program bytes, requirement,
   target descriptor, and a request fixture, then reports accepted roots.
2. Align `octra-inference` target output with the VM target fields:
   `program_root`, `requirement_root`, `model_root`,
   `execution_descriptor_root`, `store_root`, `session_abi_root`, and
   `entrypoints`.
3. Add immutable range reads over authenticated model data with a scalar
   synthetic fixture before using Bonsai data.
4. Add bounded tensor ingress and explicit-epsilon normalization as the first
   Phase 3 primitives.
5. Add the minimum local session runner: open, one advance, status, finalize,
   and cancel with candidate rollback.
6. Point the existing Bonsai runtime-proof command at the new VM harness and
   require exact token, hidden, norm, logits, requirement, target, request, and
   output roots.

## Demo Gate

Run the demo only when all of these are true:

- LiteNode builds from a clean branch with PVAC unavailable;
- `dune runtest test`, `dune build @check`, and `dune build` pass on the VPS;
- runtime source scan passes;
- `octra-inference` can reproduce the candidate packet from Git-tracked
  sources and rooted model artifacts;
- the LiteNode harness accepts the requirement and target before execution;
- every failed admission case leaves no session or output state;
- the Bonsai canary produces the expected token sequence and internal roots;
- local evidence records the exact LiteNode binary and source roots; and
- the final output clearly says `consensus_accepted=false`.

## First Follow-Up After Demo

After the local demo works, the next engineering focus is not more model
specialization. It is the generic tensor and session substrate: authenticated
range access, bounded candidate writes, effort roots, deterministic rollback,
and receipts. Bonsai then becomes one qualification target for that substrate,
not a reason to add a Bonsai lane to the VM.
